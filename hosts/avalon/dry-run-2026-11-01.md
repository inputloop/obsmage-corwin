# Avalon dry run, 2026-11-01 (read-only on the live OBS folder)

What was run, what it printed, and what I make of it. The first part is observed; the second part
is judgement. Nothing was written to `%APPDATA%\obs-studio`.

## Observed

How: Avalon's OBS folder (`C:\Users\corwi\AppData\Roaming\obs-studio`) read through the mount from
a Linux shell on Avalon, Python 3.10 there (Python 3.8 checked separately, see TEST-CARD.md).
`ls -l` of 62 config files (`global.ini`, `user.ini`, every profile file, every scene collection)
before and after: identical sizes and times, so nothing in that list changed.

1. `omg_atoms.py verify <live folder>`, first try: a Python traceback
   (`ValueError: substring not found` in `parse_kv`). Cause: three profiles
   (`EmacsConf`, `corwin2021`, `obswebservicecorwin`) have LF line endings with CRLF lines
   appended at the end, and the tool assumed one kind per file.
2. After that was fixed: `MISMATCH plugin_config/obs-browser/FirstPartySetsPreloaded/2025.7.24.0/sets.json`.
   Cause: that file is one JSON document per line (Chromium's list), not one JSON document; the
   tool kept it on split but never wrote it back on join.
3. After both fixes (obsmage commit `f73752c`): `verify: ok, lossless and no secret in the atoms`.
   Split of the whole folder: `99631 plain, 22 path, 224 device, 51 secret`. The 51 secret values
   went to a scratch vault in the Linux shell's temporary space and were not copied anywhere.
4. `omg_compose.py audit` on the active collection: byte-for-byte the same text as
   `audit-MISC_MULTI_POINT_RECORDING.txt` already in this folder (14 captures: 2 by index, 11 by
   stable id, 1 unbound). The five points raised in RECIPE.md still stand.
5. Atoms against the live files (what changed since the recipe was first made):
   - Both scene collections: identical.
   - `GSUS_Tech/basic.ini`: now starts with a byte-order mark (OBS rewrote it on 2026-11-01 at
     06:56 UTC) and the saved window layout (`DockState`) changed. Nothing else.
   - `GSUS_Tech/service.json` and `streamEncoder.json`: not in the recipe before, now added (the
     stream key shows only as `@secret(len=44)`).
   - The other 14 profiles are still not in this recipe.
   `atoms/` and `STAGES.md` were refreshed for that profile; `SCENES.md` did not need to change.
6. `compose` for the active collection using `displays-inferred.json`, written with `--out` to a
   scratch file (not kept): see `compose-dryrun-inferred-layout-2026-11-01.txt` and
   `audit-MISC-with-inferred-layout-2026-11-01.txt`. All 8 displays in that file have no stable id.

## Judged

- The compose result from the inferred layout is not worth acting on. With no ids, the audit finds
  "no current display" for every id-bound capture, and compose would create 5 new sources, add 14
  screen-map items and hide 10 existing ones. That is the tool doing what it was told with a list
  that cannot say which screen is which. The cure is the real list: `omg_compose.py displays` on
  Windows (TEST-CARD.md, step 4). Then run audit and compose again.
- The two profile-file faults were real, would have hit the first full split on Windows, and are
  now covered by tests that fail on the old code.
- Falsifier for "the live config did not change while I looked": a changed size or time in the
  before/after list. There was none.
